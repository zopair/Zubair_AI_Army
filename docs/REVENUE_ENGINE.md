# ZOPAIR Revenue Engine

## Objective

Turn ZOPAIR ARMY into a measurable economic operating system: discover opportunities, build useful products, sell them, measure unit economics, and reinvest only under explicit policy.

## Revenue lanes

1. Paid APIs / micro-SaaS
2. Digital assets, skills and workflows
3. Open-source bounties
4. Agent/skill marketplace
5. Enterprise deployments
6. Treasury and investment research (later; isolated from product operations)

## Core loop

Opportunity Scout -> Product Builder -> Verification Judge -> Release -> Customer/Usage -> Revenue Ledger -> Unit Economics -> Improvement

## Unit economics

For every revenue-producing run record:

- gross revenue
- compute cost
- API cost
- storage/bandwidth cost
- refunds/failure cost
- acquisition cost when known
- net contribution
- execution latency
- quality score

A lane is promoted only when contribution is positive over a meaningful sample and reliability/security gates remain healthy.

## Financial separation

- Operating wallet: approved infrastructure expenses only.
- Reserve: protects continuity.
- Treasury: retained earnings under policy.
- Investment: separate future subsystem; no automatic trading in v0.1.

No agent can invent destinations, increase limits, grant itself permissions, or move treasury funds outside an explicit allowlist.
