# ActiveCampaign integration handover

**Status: template implemented; live account connection is not configured or tested.** No access to the client's ActiveCampaign account was provided.

## What is in the samples

Both opt-in forms use the standard ActiveCampaign inline full-form POST pattern:

- method="POST"
- action="https://YOUR_ACCOUNT.activehosted.com/proc.php"
- Hidden controls: u, f, s, c, m, act, and v
- Contact fields named fullname and email
- Client-side name/email validation, accessible labels, and bilingual status messages

The values YOUR_ACCOUNT, YOUR_USER_ID, and FORM_ID are deliberate placeholders. They must be replaced with values copied from the client's own ActiveCampaign Full Embed code. Do not guess these values or expose API credentials in browser code.

ActiveCampaign documents the inline form publishing process and its Full Embed option here: [Publish a form to your website](https://help.activecampaign.com/hc/en-us/articles/115001257184-How-to-publish-a-form-to-your-website) and [Find a form's HTML code](https://help.activecampaign.com/hc/en-us/articles/115000850870-Where-can-I-find-my-form-s-HTML-code).

## Setup steps for the client

1. In ActiveCampaign, open Website → Forms, create or select an Inline form, and include the standard Full Name and Email fields.
2. Open Integrate → Full Embed. Copy the account hostname and exact hidden-field values from the generated code. Replace the placeholders in both sample HTML files; preserve the values generated by the account rather than assuming that u and f are interchangeable.
3. Confirm that the form is associated with the intended list and that the consent language, privacy policy, and any required double-opt-in settings match the client's legal requirements.
4. In Automations, create an automation triggered by submission of this specific form. Add the agreed tag/segmentation step if needed, then send an email containing the approved guide download URL. The guide should be hosted at a stable, client-controlled HTTPS URL.
5. Configure the form's post-submission destination to return to the landing page with ?ac=success (or a dedicated thank-you page). The sample page also displays a bilingual error state when opened with ?ac=error; the actual ActiveCampaign failure/validation behavior must be confirmed in the client's account.
6. Submit test contacts with permission, verify the contact record, list/consent state, automation enrollment, and guide email delivery. Remove test contacts afterward if requested.

## What the client must provide

- ActiveCampaign account subdomain (the YOUR_ACCOUNT part).
- The official Full Embed code or its exact u, f, s, c, m, act, and v values.
- The correct list, form, consent wording, privacy-policy URL, and double-opt-in decision.
- Approved guide file/URL, sender identity, email copy, and automation requirements.
- Desired post-submit destination and any account-specific error/thank-you behavior.

## Scope and verification

The HTML pattern and local validation are implemented in both demos. A real subscription, cross-domain POST, automation trigger, and email delivery are **not verified** because account-specific values and account access were not supplied. The current browser form submits directly to ActiveCampaign when correctly configured; it does not use an API key or an AJAX proxy.
